# Приватный навык Алисы с YandexGPT

Минимальный рабочий backend для приватного навыка Алисы. Яндекс Диалоги передают реплику в Yandex Cloud Function, функция вызывает YandexGPT Lite 5 с отдельным system prompt и возвращает сгенерированный ответ по протоколу Алисы 1.0.

## Что реализовано

- прямой backend для варианта «Функция в Яндекс Облаке»;
- реальные синхронные запросы к YandexGPT;
- редактируемая персона в `src/system-prompt.ts`;
- контекст текущей сессии через `session_state`;
- внутренний таймаут модели 3,2 секунды;
- ответы Алисы не длиннее 1024 символов;
- fallback для таймаутов, фильтрации, ошибок авторизации и провайдера;
- быстрый ответ `pong` на проверочные запросы Диалогов;
- unit-тесты без сетевых обращений.

История существует только внутри текущей сессии Алисы. Она ограничена 900 байтами, поэтому число сохранённых реплик зависит от их длины. Между сессиями контекст не сохраняется.

## Требования

- Node.js 22 или новее;
- npm;
- утилита `zip` для сборки deployment-архива;
- аккаунт Yandex Cloud с активным платёжным аккаунтом;
- каталог Yandex Cloud;
- сервисный аккаунт с ролью `ai.languageModels.user` на каталог;
- приватный навык в [Яндекс Диалогах](https://dialogs.yandex.ru/developer/).

Вызовы Cloud Functions из навыка, подключённого штатным способом, не тарифицируются. Запросы к YandexGPT оплачиваются отдельно по тарифам AI Studio.

## Локальная проверка

```bash
npm ci
npm run typecheck
npm test
npm run package
```

Последняя команда создаст `alice-yandexgpt-skill.zip`. В корне архива должен находиться `index.js`; папок `src`, `tests` и `node_modules` в архиве нет.

Для локального реального вызова YandexGPT можно использовать API-ключ сервисного аккаунта, но unit-тестам он не нужен. Не добавляйте `.env` и ключи в Git.

## Настройки

| Переменная | Обязательна | Значение по умолчанию | Назначение |
|---|---:|---:|---|
| `YANDEX_FOLDER_ID` | да | — | Идентификатор каталога Yandex Cloud |
| `YANDEX_GPT_MODEL` | нет | `yandexgpt-5-lite` | Имя модели в URI `gpt://<folder-id>/<model>` |
| `YANDEX_API_KEY` | нет | — | Запасная авторизация для локального запуска |
| `LLM_TIMEOUT_MS` | нет | `3200` | Таймаут обращения к модели, максимум 4000 мс |
| `LLM_MAX_TOKENS` | нет | `180` | Максимум токенов в генерации |
| `LLM_TEMPERATURE` | нет | `0.8` | Температура от 0 до 1 |

В Cloud Function постоянный API-ключ не нужен: код в первую очередь использует временный IAM-токен прикреплённого сервисного аккаунта из `context.token.access_token`.

## Изменение характера

Отредактируйте `src/system-prompt.ts`, затем заново выполните:

```bash
npm test
npm run package
```

Персона может просить модель говорить грубо и неформально, однако фактический ответ остаётся под фильтрами YandexGPT и правилами платформы. Реализация не пытается их обходить.

## Развёртывание через консоль Yandex Cloud

### 1. Создайте сервисный аккаунт

1. Откройте нужный каталог в консоли Yandex Cloud.
2. Перейдите в **Сервисные аккаунты** и создайте аккаунт, например `alice-yandexgpt-skill-sa`.
3. На уровне каталога назначьте ему роль `ai.languageModels.user`.

Этой роли достаточно для вызова модели. Не создавайте API-ключ для production-функции: она получит IAM-токен автоматически.

### 2. Соберите архив

```bash
npm ci
npm run typecheck
npm test
npm run package
unzip -t alice-yandexgpt-skill.zip
```

### 3. Создайте Cloud Function

1. Откройте **Cloud Functions** → **Создать функцию**.
2. Назовите её, например `alice-yandexgpt-skill`.
3. Создайте версию со следующими параметрами:

   - среда выполнения: **Node.js 22**;
   - источник кода: **ZIP-архив**;
   - архив: `alice-yandexgpt-skill.zip`;
   - точка входа: `index.handler`;
   - память: **128 МБ**;
   - таймаут выполнения: **5 секунд**;
   - сервисный аккаунт: `alice-yandexgpt-skill-sa`;
   - переменная окружения `YANDEX_FOLDER_ID`: идентификатор текущего каталога.

4. При желании добавьте `YANDEX_GPT_MODEL`, `LLM_TIMEOUT_MS`, `LLM_MAX_TOKENS` и `LLM_TEMPERATURE`. Не задавайте `YANDEX_API_KEY`, если версия функции запускается с сервисным аккаунтом.
5. Сохраните версию и дождитесь статуса `ACTIVE`.

Делать функцию публичной для штатного подключения к Диалогам не требуется.

### 4. Дайте своему аккаунту право подключить функцию

Аккаунт, под которым открыты Яндекс Диалоги, должен видеть и иметь право запускать функцию. Необходимое разрешение входит в роль `functions.functionInvoker` и более широкие роли. Назначьте её на функцию или каталог, если функция не появляется в списке backend.

### 5. Создайте приватный навык

1. Откройте [консоль Яндекс Диалогов](https://dialogs.yandex.ru/developer/) и создайте навык Алисы.
2. В поле **Backend** выберите **Функция в Яндекс Облаке**.
3. Выберите созданную функцию. Не вставляйте произвольный URL и не добавляйте HTTP-обёртку вокруг ответа функции.
4. Включите опцию **Использовать хранилище данных в навыке**. Она нужна для возврата `session_state` в следующем запросе.
5. Выберите **приватный** тип доступа.
6. Заполните обязательные поля, активационное имя и иконку, затем сохраните навык.

## Развёртывание через `yc` CLI

Установите и инициализируйте `yc`, выберите нужные облако и каталог, затем задайте свои значения:

```bash
export YC_FOLDER_ID="<идентификатор-каталога>"
export YC_SERVICE_ACCOUNT_ID="<идентификатор-сервисного-аккаунта>"
```

Создать сервисный аккаунт можно командой:

```bash
yc iam service-account create --name alice-yandexgpt-skill-sa
yc iam service-account get --name alice-yandexgpt-skill-sa
```

Назначьте сервисному аккаунту право вызова языковых моделей на каталог:

```bash
yc resource-manager folder add-access-binding "$YC_FOLDER_ID" \
  --role ai.languageModels.user \
  --subject "serviceAccount:$YC_SERVICE_ACCOUNT_ID"
```

Соберите архив и создайте функцию:

```bash
npm ci
npm test
npm run package

yc serverless function create --name alice-yandexgpt-skill

yc serverless function version create \
  --function-name alice-yandexgpt-skill \
  --runtime nodejs22 \
  --entrypoint index.handler \
  --memory 128m \
  --execution-timeout 5s \
  --service-account-id "$YC_SERVICE_ACCOUNT_ID" \
  --environment "YANDEX_FOLDER_ID=$YC_FOLDER_ID" \
  --source-path alice-yandexgpt-skill.zip
```

После создания версии подключите функцию к навыку через интерфейс Диалогов. Для прямого варианта «Функция в Яндекс Облаке» отдельный публичный HTTPS URL не нужен.

## Проверка навыка

1. В Диалогах откройте вкладку **Тестирование**.
2. Начните новую сессию. На пустой запуск функция должна вернуть локальное приветствие без расхода токенов YandexGPT.
3. Отправьте, например: `Как дела?`
4. Убедитесь, что ответ меняется между запросами и генерируется моделью.
5. Задайте связанный уточняющий вопрос. В пределах текущей сессии модель получит сохранённую историю, пока она помещается в 900 байт.

При голосовом запуске пользователь сначала произносит активационную фразу навыка, а затем задаёт вопрос. Если Диалоги передадут вопрос вместе с запуском как непустой `request.command`, функция сразу вызовет YandexGPT.

## Обработка ошибок

Функция всегда старается вернуть корректный ответ протокола Алисы с `end_session: false`:

- таймаут модели — короткая просьба повторить запрос;
- `401` или `403` — сообщение о проблеме настройки; проверьте сервисный аккаунт, роль и каталог;
- `429` — временная недоступность; проверьте квоты AI Studio;
- `5xx` или сетевая ошибка — временный fallback без повторного запроса;
- `ALTERNATIVE_STATUS_CONTENT_FILTER` — объяснение, что модель не смогла ответить;
- пустой или неожиданный JSON — безопасный fallback;
- слишком длинный ответ — обрезка до 1024 символов;
- история больше лимита — удаление старейших полных пар сообщений.

В одном webhook-запросе нет автоматического retry: общий лимит ожидания Диалогов составляет 4,5 секунды. Внутренний таймаут YandexGPT по умолчанию равен 3,2 секунды.

## Логи и диагностика

Логи доступны на странице функции в Yandex Cloud. Для запроса к модели записываются только категория результата, HTTP-статус ошибки, длительность и `session_id`. API-ключи, IAM-токены и полный разговор не логируются.

Если навык сообщает, что не может разобрать запрос, проверьте, что в Диалогах выбран backend **Функция в Яндекс Облаке**, а функция возвращает объект протокола напрямую. Для raw-интеграции нельзя возвращать `{ statusCode, body }`.

Если контекст не сохраняется, включите хранилище навыка и проверьте, что ответ содержит `session_state`. Память процесса Cloud Function намеренно не используется и не гарантируется между вызовами.
