# Приватный навык Алисы с YandexGPT: дизайн MVP

Дата: 2026-10-08

## 1. Цель

Создать минимальный, но реально работающий приватный навык Алисы. Пользователь обращается к навыку голосом или текстом, Яндекс Диалоги вызывают Yandex Cloud Function, функция отправляет реплику в YandexGPT с заданной персоной и возвращает сгенерированный ответ в формате протокола Алисы 1.0.

Успешный результат: во вкладке тестирования Яндекс Диалогов пользователь отправляет обычную реплику, например «Как дела?», и получает ответ, сгенерированный YandexGPT через Cloud Function, а не локальным набором правил.

## 2. Ограничения и границы MVP

- Node.js 22 и TypeScript.
- Backend размещается в Yandex Cloud Functions.
- LLM — YandexGPT через синхронный REST API генерации текста.
- Навык предназначен для приватного использования. Публичная публикация грубой персоны с матом может не соответствовать требованиям Яндекс Диалогов.
- System prompt хранится отдельно от обработчика и легко редактируется.
- Контекст сохраняется только в пределах текущей сессии Алисы.
- База данных, аккаунты, веб-интерфейс, Docker, API Gateway и сложная инфраструктура не входят в MVP.
- Реализация не обходит ограничения Яндекс Диалогов, Yandex Cloud или модели. Заблокированный провайдером ответ заменяется понятным fallback-сообщением.

## 3. Подтверждённые ограничения платформы

- Диалоги отправляют webhook как POST-запрос протокола 1.0. Текст команды находится в `request.command`, полная исходная реплика — в `request.original_utterance`, новая сессия определяется по `session.new`.
- Ответ содержит обязательные `response.text`, `response.end_session` и `version` со значением `1.0`.
- `response.text` ограничен 1024 символами.
- Полный ответ webhook должен быть получен Диалогами не позднее 4,5 секунды после начала запроса, включая сетевые задержки.
- При прямом выборе Cloud Function в настройках навыка используется raw-интеграция: функция получает объект протокола Алисы и возвращает объект протокола Алисы без HTTP-обёртки `statusCode/body`.
- `session_state` хранится платформой до конца сессии и ограничен 1 КБ.
- Память экземпляра Cloud Function не считается надёжным хранилищем между вызовами.
- YandexGPT принимает сообщения с ролями `system`, `user` и `assistant`.

## 4. Архитектура

Весь backend является одной Cloud Function. Внутри кода обязанности разделены между небольшими модулями:

```text
Яндекс Диалоги
    -> index.handler
       -> проверка запроса и специальные ветки
       -> чтение истории из state.session
       -> conversation: нормализация и ограничение истории
       -> yandex-gpt: вызов REST API с таймаутом
       -> alice: формирование ответа протокола 1.0
    -> Алиса показывает и озвучивает response.text
```

Структура исходного кода:

```text
src/
  index.ts
  alice.ts
  yandex-gpt.ts
  conversation.ts
  system-prompt.ts
  config.ts
tests/
  handler.test.ts
  alice.test.ts
```

Назначение модулей:

- `index.ts` экспортирует production-handler и внутреннюю фабрику обработчика с внедряемым LLM-клиентом.
- `alice.ts` содержит минимальные типы входного и выходного протокола, извлечение команды и построение ответа.
- `yandex-gpt.ts` формирует REST-запрос, выбирает авторизацию, применяет таймаут и разбирает ответ модели.
- `conversation.ts` валидирует, дополняет и сокращает историю сессии.
- `system-prompt.ts` экспортирует единственный редактируемый system prompt.
- `config.ts` читает и проверяет переменные окружения.

## 5. Поток обработки запроса

1. Обработчик принимает объект webhook и контекст Cloud Function.
2. Если `request.original_utterance` равен `ping`, обработчик немедленно возвращает `pong` без вызова LLM.
3. Обработчик проверяет минимально необходимые поля запроса.
4. Для новой сессии входящая история игнорируется.
5. Если новая сессия не содержит команды, возвращается локальное приветствие без вызова модели.
6. Пустая команда в продолжающейся сессии вызывает короткую просьбу повторить вопрос.
7. Для непустой команды формируется список сообщений: system prompt, сохранённая история, текущая реплика пользователя.
8. YandexGPT вызывается один раз с внутренним таймаутом.
9. Успешный текст очищается от лишних пробелов и ограничивается 1024 символами по границе предложения или слова, когда это возможно.
10. Успешная пара сообщений пользователя и ассистента добавляется в историю.
11. История сокращается до безопасного размера и возвращается в `session_state`.
12. Ответ всегда продолжает сессию: `response.end_session` равен `false`.

## 6. Персона

System prompt задаёт альтернативного голосового собеседника со следующими свойствами:

- говорит по-русски, неформально и прямо;
- может быть грубым и использовать мат, если запрос и ограничения модели это допускают;
- не имитирует корпоративного помощника и избегает шаблонных вводных;
- отвечает достаточно кратко для голосового интерфейса;
- может обсуждать обычные пользовательские темы;
- использует переданную историю текущей сессии;
- не представляется официальной Алисой или официальным продуктом Яндекса;
- не пытается обходить фильтры или правила провайдера.

Фактическая генерация остаётся под ограничениями YandexGPT. Наличие инструкции о допустимости мата не гарантирует, что модель выдаст такой текст.

## 7. YandexGPT и авторизация

Функция обращается к синхронному REST API генерации текста через встроенный в Node.js 22 `fetch`. Streaming, tool calls и reasoning для MVP не используются.

Приоритет способов авторизации:

1. IAM-токен прикреплённого к версии функции сервисного аккаунта из контекста Cloud Function.
2. `YANDEX_API_KEY` из окружения для локального запуска или резервной конфигурации.

Сервисному аккаунту назначается роль `ai.languageModels.user`. Токены и ключи не включаются в логи и сообщения об ошибках.

Переменные окружения:

- `YANDEX_FOLDER_ID` — обязательный идентификатор каталога.
- `YANDEX_GPT_MODEL` — необязательное имя модели; по умолчанию `yandexgpt-5-lite`.
- `YANDEX_API_KEY` — необязательный API-ключ для запуска без IAM-контекста.
- `LLM_TIMEOUT_MS` — внутренний таймаут, по умолчанию 3200 мс.
- `LLM_MAX_TOKENS` — ограничение длины генерации, по умолчанию 180 токенов.
- `LLM_TEMPERATURE` — температура генерации, по умолчанию `0.8`.

Для MVP выбрана YandexGPT Lite 5: это самая небольшая и быстрая модель семейства, что важнее дополнительного качества внутри лимита ответа Диалогов 4,5 секунды. Значение `modelUri` формируется как `gpt://<YANDEX_FOLDER_ID>/<YANDEX_GPT_MODEL>`, то есть по умолчанию `gpt://<YANDEX_FOLDER_ID>/yandexgpt-5-lite`. Формат запроса и URI фиксируются unit-тестом.

## 8. История диалога

История хранится не в памяти процесса, а в поддерживаемом Диалогами `session_state`:

```json
{
  "v": 1,
  "history": [
    { "role": "user", "text": "Как дела?" },
    { "role": "assistant", "text": "Нормально..." }
  ]
}
```

После успешной генерации код добавляет полную пару `user`/`assistant`, сериализует объект в UTF-8 и удаляет самые старые полные пары, пока размер не станет не больше 900 байт. Порог оставляет запас относительно платформенного лимита 1 КБ.

Количество сохранённых сообщений динамическое. Шесть–десять коротких сообщений могут поместиться, но MVP не обещает фиксированное количество. На новой сессии история начинается заново. При ошибке LLM возвращается предыдущий state без добавления ошибочной пары.

## 9. Таймауты и обработка ошибок

Общий лимит Диалогов равен 4,5 секунды, поэтому вызов модели прерывается через `AbortController` примерно через 3,2 секунды. В одном webhook-запросе нет автоматических повторов.

Пользователь получает короткий корректный ответ Алисы в следующих случаях:

- пустая команда;
- некорректный или неполный webhook, если ответ протокола ещё возможно сформировать;
- таймаут модели;
- ошибки авторизации YandexGPT;
- rate limit или серверная ошибка провайдера;
- пустой, некорректный или отфильтрованный ответ модели.

Ошибки не завершают сессию. Логи содержат категорию ошибки, HTTP-статус, длительность и идентификатор сессии, но не секреты и не полную историю разговора.

Если входное значение настолько некорректно, что не является вызовом навыка, функция всё равно предпочитает вернуть минимальный объект ответа протокола 1.0 вместо выброса необработанного исключения.

## 10. Формат ответа

Минимальный ответ имеет вид:

```json
{
  "response": {
    "text": "Ответ модели",
    "end_session": false
  },
  "session_state": {
    "v": 1,
    "history": []
  },
  "version": "1.0"
}
```

Поле `tts` в MVP не требуется: согласно протоколу `response.text` используется для показа и озвучивания. Карточки, кнопки, директивы и аналитика не добавляются.

## 11. Тестирование

Тесты используют встроенные `node:test` и `node:assert`. Сетевой клиент внедряется в обработчик, поэтому unit-тесты не обращаются к YandexGPT.

Обязательные сценарии:

- извлечение `request.command`;
- быстрый `pong` без LLM;
- приветствие новой пустой сессии без LLM;
- вызов LLM для новой сессии с непустой командой;
- вызов LLM для продолжающейся сессии;
- точный контракт `response.text`, `response.end_session` и `version`;
- передача истории в модель и очистка истории при новой сессии;
- ограничение сериализованного `session_state` безопасным размером;
- ограничение ответа 1024 символами;
- fallback при таймауте, HTTP-ошибке, фильтрации и пустом ответе;
- сохранение прежней истории при ошибке;
- формирование запроса YandexGPT и выбор схемы авторизации.

Проверка перед завершением реализации включает компиляцию TypeScript, полный запуск тестов и проверку содержимого deployment-архива.

## 12. Сборка и развёртывание

Runtime-зависимости не планируются. Dev-зависимости ограничены TypeScript и типами Node.js. Компиляция создаёт JavaScript, совместимый с Node.js 22. ZIP-архив содержит скомпилированные файлы, необходимые для точки входа `index.handler`.

Рекомендуемые параметры версии Cloud Function:

- runtime: Node.js 22;
- entry point: `index.handler`;
- execution timeout: 5 секунд;
- память: минимально достаточное значение, первоначально 128 МБ;
- сервисный аккаунт с ролью `ai.languageModels.user`;
- переменные окружения из раздела 7.

В Яндекс Диалогах backend выбирается как «Функция в Яндекс Облаке», а не как произвольный публичный webhook URL. У аккаунта, который подключает функцию, должно быть разрешение на её вызов, входящее в `functions.functionInvoker` или более широкую роль. Для сохранения истории в настройках навыка включается хранилище данных. Тип доступа навыка — приватный.

README описывает сборку, создание сервисного аккаунта, роли, создание функции и версии через консоль, эквивалентный путь через `yc` CLI, настройку Диалогов, тестирование и диагностику ошибок. В нём отдельно указывается, что вызовы Cloud Functions из корректно подключённого навыка не тарифицируются, но генерация YandexGPT тарифицируется отдельно.

## 13. Не входит в MVP

- долговременная история между сессиями;
- внешняя база данных или кеш;
- авторизация пользователей навыка;
- streaming-ответы;
- собственный синтез речи;
- web UI;
- Docker и контейнеры;
- API Gateway;
- публикация навыка в общем каталоге;
- обход фильтров или ограничений платформы.
